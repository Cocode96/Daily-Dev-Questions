# SB Packer

파일을 `SBPacker.exe` 아이콘 위에 놓으면 원본과 같은 폴더에 `.sb` 파일을 만든다. 파일 종류를 해석하지 않고 원본 바이트에 파일명과 크기 정보를 붙여 저장하는 작은 도구다. SB는 Seok Binary의 약자로 사용한다.

## 사용 방법

빌드한 `dist/SBPacker.exe`를 원하는 위치에 두고 파일 하나 또는 여러 개를 EXE 아이콘 위로 드래그한다. Python을 별도로 설치하지 않은 Windows x64 컴퓨터에서도 실행할 수 있도록 패키징했다.

```text
입력: C:\Assets\image.png
결과: C:\Assets\image.png.sb

같은 파일을 다시 놓으면:
      C:\Assets\image.png (1).sb
```

결과 창에는 완료한 파일의 경로와 실패한 파일의 이유가 표시된다. Enter 키를 누르면 종료한다. EXE만 더블클릭하면 사용 안내가 나온다.

원본과 기존 결과 파일은 덮어쓰지 않는다. 폴더는 처리하지 않으며, 여러 파일 중 하나가 실패해도 나머지 파일은 계속 처리한다. 저장 중 실패하면 이번에 만들던 불완전한 결과 파일을 제거한다.

명령줄에서도 실행할 수 있다.

```powershell
.\SBPacker.exe "C:\Assets\image.png" "C:\Assets\설정 파일.json"
```

이 버전에는 복원, 압축, 암호화 기능이 없다. 원본 파일도 이미 바이트로 저장되어 있으며, 이 도구는 자체 컨테이너 형식을 추가한다. 텍스트를 넣으면 본문의 텍스트 바이트가 그대로 포함되고, 이미지는 디코딩하거나 엔진용 리소스로 변환하지 않는다. 출력 크기는 원본보다 16바이트와 UTF-8 파일명 길이만큼 커진다.

## 빌드와 확인

Windows x64와 `uv`가 필요하다. 이 폴더에서 실행하면 Python 3.13 환경과 빌드 의존성을 준비하고 테스트 후 단일 EXE를 만든다.

```powershell
.\build.ps1
```

결과는 `dist/SBPacker.exe`에 생성된다. 가상 환경, 빌드 임시 파일과 EXE는 Git에 포함하지 않는다. EXE 패키징에는 [PyInstaller의 one-file 옵션](https://pyinstaller.org/en/stable/usage.html)을 사용한다.

소스 실행과 테스트는 다음과 같다.

```powershell
.\.venv\Scripts\python.exe sb_packer.py "C:\Assets\image.png"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

2026-09-14, Windows 11 x64 / Python 3.13.14 / PyInstaller 6.22.2에서 빌드하고 단위 테스트 7개를 통과했다. 빌드한 EXE에 파일 경로를 전달해 다중 입력, 한글과 공백 및 이모지 경로, 빈 파일, 바이너리 파일, 입력 폴더에 저장, 원본 보존, 이름 충돌, 잘못된 경로 처리와 인자 없는 실행을 확인했다. 결과의 헤더, 파일명과 전체 본문을 원본과 대조했다. 탐색기에서 마우스로 드롭하는 동작은 직접 검증하지 않았다.

## SB 형식 v1

헤더의 정수는 little endian이다. 파일명에는 디렉터리 없이 원본 이름과 확장자만 저장한다. 파일 본문은 최대 1 MiB씩 읽고 쓴다.

| 위치 | 크기 | 내용 |
|---|---:|---|
| 0 | 4바이트 | 식별자 `SBIN` |
| 4 | 2바이트 | 버전, 현재 `1` |
| 6 | 2바이트 | UTF-8 파일명의 바이트 수 N |
| 8 | 8바이트 | 원본 파일 크기 M |
| 16 | N바이트 | UTF-8 원본 파일명 |
| 16 + N | M바이트 | 원본 파일의 바이트 |

원본 파일은 변환이 끝날 때까지 수정하지 않는 것을 전제로 한다. 읽는 동안 파일 크기나 수정 시각의 변경이 감지되면 실패로 처리하지만, 파일의 동시 수정을 잠그는 기능은 제공하지 않는다.
